# The PRE-PRINT bridge profile (send-flow S4b): the commands registered on the SnapmakerDeviceBridge built with Options::preprint_session,
# i.e. the pre-print dialog's webview. Same format and same bundle gate as snapmaker_bridge_commands.txt (which is the DEVICE TAB's list and
# is not changed by this profile). Checked by scripts/verify_bridge_commands.cmake (every bundle name classified, nothing stale) and by the
# [SSWCP][preprint_profile][list] Catch2 test (the live registry of that profile equals the REGISTERED lines).
# REGISTERED here = the core's 13 built-in commands (SSWCP cannot unregister them; none touches the printer) + sw_GetConnectedMachine + the seven
# pre-print commands, each answered by SnapmakerPreprintSession (docs/records/snapmaker-u1-send-flow-design.md section 3) + (#137, ADR 0010
# amendment 2026-11-17) the Device tab's READ-ONLY family: machine state / subscribe, system info, the cache, MQTT and filament-info stubs. Each of
# those answers only for the pinned printer of the live epoch (stale or closed = empty reply, nothing contacted) and sends at most a read.
# Everything else is DENIED (501): uploads, downloads, deletes, renames, purifier, nozzle temperature, SendCommand and the Device tab's machine
# controls. The 12 names the parity audit found unrecorded (sw_AddDevice, sw_Connect, sw_ConnectOtherMachine, sw_Disconnect, sw_GetPincode,
# sw_StartMachineFind, sw_StopMachineFind, sw_DeleteDevices, sw_DeleteRecentFiles, sw_mqtt_set_engine, sw_test_mqtt_moonraker, sw_SnapLog) stay
# DENIED (ADR 0010); sw_SnapLog is undecided.
# sw_StartLocalPrint is answered -1/"failure" on purpose (the page then falls back to the validated script + printer.print.start).
